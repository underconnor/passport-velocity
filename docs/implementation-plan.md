# Velocity 플러그인 구현 계획

## 신뢰 경계

- 정품 Java 계정만 허용하며 프록시는 online mode로 운영합니다.
- 사용자 이름보다 정품 인증된 Minecraft UUID를 연결 키로 사용합니다.
- 서버가 보고한 UUID를 신뢰할 수 있도록 Paper의 modern forwarding과 백엔드 네트워크 접근 제한을 함께 구성합니다.
- API 서비스 자격 증명은 런타임 설정으로 주입하고 저장소에 넣지 않습니다.
- 학교 학적과 명부 내용은 프록시로 전달하지 않고 접근 판정에 필요한 최소 정보만 사용합니다.

## NanoLimbo 대기 흐름

1. 미인증 접속자를 대기 서버로 보냅니다. 대기 서버의 역할은 연결을 유지하는 것입니다.
2. Velocity가 API에서 짧은 수명의 일회용 연결 요청을 만들고 해당 플레이어에게만 웹 URL을 전송합니다.
3. 링크는 채팅의 클릭 동작으로 제공합니다. 고정 NanoLimbo 안내 문구에 모든 사용자용 공통 토큰을 넣지 않습니다.
4. 사용자가 웹에서 학교 인증과 대상 계정 확인을 마치면 `게임 확인 대기`로 표시합니다.
5. 같은 UUID의 현재 접속 세션에서 `/passport confirm`을 실행해야 API가 연결을 확정합니다.
6. 최신 접근 정책을 다시 조회한 뒤 허용된 서버로 보냅니다.

URL을 열기만 하거나 웹 확인만 완료한 상태에서는 Minecraft 연결을 활성화하지 않습니다. 요청 만료, 한 번 사용한 요청 재사용, 다른 UUID의 확인, 재접속 시 요청 처리 기준은 API와 함께 구현합니다.

처음에는 책·인벤토리 GUI 없이 채팅 링크와 명령어로 구현합니다. NanoLimbo의 현재 배포판이 운영 중인 Minecraft 프로토콜을 지원하는지, 연결 후 Velocity 메시지와 명령 처리가 작동하는지 PoC에서 확인합니다.

## 서버 접근 검사

- 최초 목적지 선택, 서버 선택기 이동, 명령어 이동, 재접속·폴백 이동을 모두 검사합니다.
- 대기 서버는 명시적으로 구분하고 보호 서버에는 기본 거부 정책을 적용합니다.
- 정책 캐시는 유효 기간과 버전을 포함합니다. 무효화되거나 만료된 허용 결과로 새 보호 서버 입장을 승인하지 않습니다.
- API 장애 시 유효 정책이 없는 신규 접속·이동은 차단합니다. 유효 lease가 남은 일반 서버는 그 범위의 이동·체류를 허용하되 만료 시 대기실로 옮깁니다. 민감 서버의 새 이동은 온라인 재검증이 필요하므로 차단합니다. 서버 재시작으로 캐시가 없으면 허가하지 않습니다.
- 정지나 권한 회수가 확인되면 영향을 받는 사용자를 대기 서버로 이동시키거나 연결을 종료합니다. 이동 실패가 보호 서버 체류로 이어지지 않게 합니다.
- API 요청으로 프록시 이벤트 스레드를 막지 않고 타임아웃·재시도 상한을 둡니다.

## 구현 완료 조건

- 정품 인증이 안 된 연결은 회원 연결 절차에 진입할 수 없습니다.
- 웹 최종 확인과 게임 확인이 모두 있어야 계정 연결이 확정됩니다.
- 미인증 사용자가 서버 선택기나 명령어로 보호 서버에 접근할 수 없습니다.
- API 장애·캐시 만료·권한 회수 후에도 허용되지 않은 새 입장이 발생하지 않습니다.
- 일회용 URL과 서비스 비밀값이 일반 로그에 출력되지 않습니다.

현재는 설계 문서만 있으며 위 동작은 아직 구현·검증하지 않았습니다.

# 정책 변경 알림과 복구

## 처리 기준

- GET `/v1/minecraft/events`는 최초 요청에서 현재 cursor와 `reset:true`를 반환합니다. plugin은 온라인 UUID 전체를 재조회합니다.
- 이후 `?after=<cursor>`로 조회하며, cursor/id는 0부터 signed 64-bit 최대값까지의 십진 문자열입니다. 부동소수점으로 바꾸지 않습니다.
- 정상 batch는 최대 500개 이벤트이며, 같은 UUID의 가장 높은 policyVersion만 확인합니다. 오프라인 UUID는 다음 입장 시 일반 정책 검사로 확인합니다.
- 이벤트는 재조회 힌트입니다. 정책 조회의 UUID·버전·lease 검사를 통과해야 기존 허용 규칙을 적용할 수 있습니다.
- 하나의 batch가 진행 중이면 다음 timer tick은 같은 작업을 공유합니다. 모든 필요한 온라인 정책 처리가 성공해야 cursor를 저장합니다. 실패하면 이전 cursor로 다시 요청합니다.
- reset의 전체 조회는 reset 응답 전에 시작한 요청이 있다면 그 요청을 기다린 뒤 새로 수행합니다. 기존 요청의 오래된 결과로 reset을 승인하지 않습니다.

## API 또는 네트워크 장애

알림 실패는 권한을 부여하거나 lease를 연장하지 않습니다. 정기 정책 조회가 계속 동작하고 기존 lease가 끝나면 Velocity는 대기 서버로 이동시키거나 종료하며 Paper는 접속을 종료합니다. API 복구 후 마지막 성공 cursor로 다시 처리합니다. 보관 기간을 벗어나면 reset으로 온라인 전체를 확인합니다.

## DB 복원과 버전 역행

`reset:true`는 outbox cursor를 복구하는 신호이며 UUID별 정책 watermark를 삭제하라는 뜻이 아닙니다. 복원된 DB가 더 낮은 policyVersion을 반환하면 plugin은 그 결과를 거부하고 cursor를 승인하지 않습니다. 기존 lease는 원래 만료 시각에 끝납니다.

운영자는 보호 서버 입장을 중지한 상태에서 복원한 회원·정지·접근 정책을 최신 운영 기록과 대조하고, 영향을 받은 UUID의 정책 버전을 plugin이 이미 본 버전보다 높게 재설정하는 복구 작업을 수행해야 합니다. 현재 저장소는 이 DB 작업을 자동으로 수행하지 않습니다. 복구 확인 후 정책 재조회 성공과 실제 권한 회수 동작을 검증합니다. plugin을 재시작하여 watermark를 지우는 방식으로 복원 오류를 우회하지 않습니다.

## 검증 범위

JUnit은 초기 reset, cursor 보존·재시도, 중복 UUID 병합, 오프라인 제외, 잘못된 cursor, DB 복원 버전 역행, 진행 중 요청 공유와 batch 동시 실행 제한을 검사합니다. 실제 정품 계정에서 관리자의 권한 회수부터 이동·종료까지 걸리는 시간과 대기실 장애 동작은 클라이언트 QA 항목입니다.
